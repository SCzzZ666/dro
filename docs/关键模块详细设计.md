## 2. Agent 编排模块

### 2.1 职责

- 管理任务从接收至完成的全生命周期状态流转
- 实现 Manager-Executor 动态反馈环，每步重新评估并决策
- 协调工具执行、记忆注入、结果汇总
- 通过 checkpoint 支持断点恢复
- 高风险动作触发 Verifier 与人工确认

### 2.3 节点详细设计

#### 2.3.1 manager_node

**职责：** 高层决策，每步执行后重新评估当前状态并决定下一步动作。

**输入：**
- 当前截图（标注前）
- 当前 Accessibility Tree
- 上一步 Accessibility Tree（差分）
- 任务目标 + 已采集数据
- 记忆上下文（会话摘要 + 长期偏好）

**输出：**
- `sub_goal`: 当前子目标（自然语言）
- `next_action`: 动作类型枚举
- `action_args`: 动作参数（如目标元素描述、输入文本）
- `reasoning`: 推理依据（用于调试与 trace）

**Prompt 结构：**
```
System: 你是手机操作 Agent 的决策管理器。根据当前屏幕状态决定下一步动作。
        可用动作：click / type / swipe / system_button / open_app / done
        规则：...（预算规则、完成判定规则、安全规则）

User:
[任务目标] {user_message}
[当前子目标] {sub_goal}
[已采集数据] {collected_summary}
[当前界面] {a11y_tree_summary}
[界面变化] {diff_summary}  # 与上一步对比
[记忆] {memory_context}

请输出 JSON：{"sub_goal": "...", "next_action": "...", "action_args": {...}, "reasoning": "..."}
```

**模型：** 强模型（Qwen-VL-Plus / DeepSeek-V3），temperature=0.1

**异常处理：**
- LLM 调用失败 → 降级为确定性规则（基于已采集数据判定完成/继续）
- 输出 JSON 解析失败 → 重试 1 次，仍失败则用默认动作（go_back）
- 达到 max_steps（默认15）→ 强制 next_action="done"

#### 2.3.2 executor_node

**职责：** 将 Manager 的高层决策转化为精确的工具调用参数。

**输入：**
- SoM 标注截图
- `next_action` + `action_args`（来自 Manager）
- `som_mapping`（编号→元素映射）

**输出：**
- 工具名 + 精确参数（如 `click(element_index=3)`）

**Prompt 结构：**
```
System: 你是执行器。根据标注图中的编号选择要操作的元素。
User:
[动作类型] click
[动作描述] 点击第一个商品卡片
[标注图] <image>
请输出 JSON：{"tool": "click", "args": {"element_index": 3}}
```

**模型：** 快模型（Qwen-VL-Turbo），temperature=0

**异常处理：**
- 元素编号超出范围 → 返回错误，Manager 重新决策
- 连续 2 次执行失败 → Manager 更换策略（如换搜索词、go_back 重试）

#### 2.3.3 verifier_node

**职责：** 对高风险动作进行二次评估，仅在 `next_action` 属于高风险清单时触发。

**高风险动作清单：** `confirm_order`、`payment`、`delete_data`、`send_message`、`add_to_cart`（可配置）

**验证逻辑：**
1. 检查动作是否与当前任务目标一致（如下单商品是否为推荐商品）
2. 检查是否有未完成的前置步骤（如未选择规格）
3. 评估通过 → 设置 `pending_confirmation`，触发 LangGraph `interrupt` 等待用户确认
4. 评估不通过 → 返回 Manager 重新决策

**用户确认流程：**
```
verifier_node → interrupt (pending_confirmation)
                     ↓
              SSE 推送 need_confirm 事件
                     ↓
              用户 POST /v2/tasks/{id}/confirm
                     ↓
              LangGraph resume → 继续执行
```

#### 2.3.4 text_agent（专用文本 Agent）

**触发条件：** Manager 判定当前子目标为文本密集型（填写表单、搜索输入、编辑文本）。

**能力：**
- 持有 Python shell，可程序化构造文本
- 原子性清空并替换输入框全部文本（避免逐字输入错误）
- 接收 Accessibility Tree（无截图），定位聚焦输入框

**执行流程：**
1. 接收 Manager 的文本任务描述
2. 通过 Accessibility Tree 定位当前聚焦输入框
3. 构造目标文本（可包含变量替换，如"预算{budget}以内的耳机"）
4. 执行 `type` 动作（剪贴板粘贴，中文自动处理）
5. 返回执行结果给主循环

#### 2.3.5 result_node

**职责：** 汇总采集数据，确定性打分，生成最终回复。

**流程：**
1. 对 `collected` 中的商品进行确定性打分（价格0.5 + 销量0.2 + 评分0.15 + 运费-0.1 + 退货险0.05）
2. 排序选出 winner（is_winner=True）
3. 调用 LLM 基于打分结果生成自然语言解释（不重新推荐，只解释为什么选这个）
4. 构造 `TaskResult`（products + recommendation + checkout_options）
5. 触发会话摘要（fire-and-forget，不阻塞响应）

### 2.4 关键设计决策

**为什么 Manager 和 Executor 分离？**
- Manager 需要理解任务全局、界面变化、已采集数据，输入 token 多，需要强模型
- Executor 只需要看标注图选编号，输入 token 少，快模型足够且延迟低
- 分离后单任务 LLM 调用：Manager 每步1次（强模型）+ Executor 每步1次（快模型），但 Executor 调用快且便宜
- 对比旧模式 planner（1次强模型）+ agent（每步1次强模型 ReAct），总成本降低约 40%

**为什么用 interrupt 而不是轮询确认？**
- LangGraph `interrupt` 原生支持暂停状态图，状态自动写入 checkpoint
- 用户确认后 `Command(resume=...)` 直接恢复，无需重新执行
- 比"保存状态到数据库+轮询+重建状态"更简洁可靠

## 3. 设备池模块

### 3.1 职责

- 管理多台 Android 设备（模拟器/真机/云手机）的注册、健康检查与生命周期
- 为每台设备维护独立 Worker 线程与 FIFO 任务队列，保证单设备串行
- 根据任务标签路由到匹配设备，支持负载均衡
- 任务完成后自动清理应用数据，防止账号串扰

### 3.2 类设计

```python
@dataclass
class DeviceInfo:
    device_id: str
    serial: str                    # ADB serial
    name: str
    device_type: str               # emulator / real_device / cloud_phone
    os_version: str
    resolution: Tuple[int, int]
    tags: List[str]                # ["taobao_logged_in", "jd_logged_in"]
    status: str                    # online / offline / busy / maintenance
    current_task_id: Optional[str]
    tasks_done: int = 0
    tasks_failed: int = 0
    last_heartbeat: float = 0.0


class DeviceWorker:
    """单设备 Worker：独立线程 + FIFO 队列 + 互斥锁。"""

    def __init__(self, device: DeviceInfo, adb_client: AdbClient):
        self.device = device
        self.adb = adb_client
        self.queue: asyncio.Queue[Task] = asyncio.Queue()
        self.lock = asyncio.Lock()
        self._running = False
        self._task: Optional[asyncio.Task] = None

    async def start(self):
        self._running = True
        self._task = asyncio.create_task(self._loop())

    async def stop(self):
        self._running = False
        if self._task:
            self._task.cancel()

    async def submit(self, task: Task) -> None:
        await self.queue.put(task)

    async def _loop(self):
        while self._running:
            task = await self.queue.get()
            async with self.lock:
                await self._execute(task)
            self.queue.task_done()

    async def _execute(self, task: Task):
        self.device.status = "busy"
        self.device.current_task_id = task.task_id
        try:
            # 绑定设备到 ADB 客户端
            self.adb.set_serial(self.device.serial)
            # 执行 Agent 编排
            result = await self._runner.ainvoke(task=task, adb=self.adb)
            task.status = "succeeded"
            task.result = result
        except Exception as e:
            task.status = "failed"
            task.error = str(e)
        finally:
            # 清理应用数据
            await self._cleanup_apps(task)
            self.device.status = "online"
            self.device.current_task_id = None
            self.device.tasks_done += 1 if task.status == "succeeded" else 0
            self.device.tasks_failed += 1 if task.status == "failed" else 0


class DevicePool:
    """设备池管理器：注册、调度、健康检查。"""

    def __init__(self):
        self.workers: Dict[str, DeviceWorker] = {}
        self._health_task: Optional[asyncio.Task] = None

    def register(self, device: DeviceInfo, adb_client: AdbClient) -> None:
        worker = DeviceWorker(device, adb_client)
        self.workers[device.device_id] = worker
        asyncio.create_task(worker.start())

    def unregister(self, device_id: str) -> None:
        worker = self.workers.pop(device_id)
        asyncio.create_task(worker.stop())

    async def schedule(self, task: Task) -> str:
        """根据任务标签路由到匹配设备，返回 device_id。"""
        candidates = self._match_devices(task.tags)
        if not candidates:
            raise NoDeviceAvailable("无匹配设备，任务排队等待")
        # 负载均衡：选队列最短的在线设备
        worker = min(candidates, key=lambda w: w.queue.qsize())
        await worker.submit(task)
        return worker.device.device_id

    def _match_devices(self, tags: List[str]) -> List[DeviceWorker]:
        return [
            w for w in self.workers.values()
            if w.device.status == "online"
            and all(t in w.device.tags for t in tags)
        ]

    async def health_check(self):
        """每 30s 执行一次，检查设备在线状态。"""
        for worker in self.workers.values():
            try:
                state = await worker.adb.get_state()  # adb get-state
                if state == "device":
                    worker.device.status = "online" if worker.device.status == "offline" else worker.device.status
                    worker.device.last_heartbeat = time.time()
                else:
                    worker.device.status = "offline"
            except Exception:
                # 自动重连
                try:
                    await worker.adb.connect(worker.device.serial)
                except Exception:
                    worker.device.status = "offline"
```

### 3.3 调度策略

| 策略 | 说明 |
|------|------|
| 标签匹配 | 任务指定所需标签（如 `taobao_logged_in`），仅匹配含全部标签的设备 |
| 最短队列 | 匹配设备中选队列长度最短的，实现负载均衡 |
| 优先级 | 队列内按 priority 排序（默认 FIFO，高优先级插队） |
| 排队等待 | 无匹配设备时任务进入全局等待队列，设备上线后自动分配 |
| 超时驱逐 | 任务在队列中等待超过 5 分钟自动取消并通知用户 |

### 3.4 健康检查机制

```
每 30s:
  for each device:
    adb get-state
    ├─ "device" → online, 更新 heartbeat
    ├─ "offline" → 尝试 adb connect 重试
    │   ├─ 成功 → online
    │   └─ 失败 (3次累计) → 标记 offline, 触发告警
    └─ 异常 → 标记 offline
```

**设备恢复后：**
- 自动重新注册到设备池
- 等待队列中匹配的任务自动分配
- 不需要人工干预

### 3.5 数据隔离

每台设备执行完任务后自动清理：
```python
async def _cleanup_apps(self, task: Task):
    packages = task.affected_packages  # ["com.taobao.taobao", "com.jingdong.app.mall"]
    for pkg in packages:
        await self.adb.shell(f"pm clear {pkg}")
```

**为什么不每次都清理所有应用？**
- `pm clear` 会清除登录态，下次任务需重新登录（耗时 30s+）
- 按任务影响的应用精准清理，兼顾隔离与效率
- 设备标签 `taobao_logged_in` 表示该设备保持淘宝登录态，不清理淘宝

## 4. 工具执行模块

### 4.1 职责

- 维护工具注册表，支持动态注册与发现
- 统一工具执行入口，提供超时保护与异常兜底
- 实现标准化原子动作空间（6类），泛化到通用手机操作
- Set-of-Mark 元素索引与坐标映射
- 屏幕稳定化等待（替代固定 sleep）

### 4.2 工具注册表

```python
@dataclass
class AgentTool:
    name: str
    description: str
    parameters: Dict[str, Any]       # JSON Schema
    implementation: Callable
    timeout: float = 10.0            # 超时秒数
    risk_level: str = "low"          # low / medium / high
    category: str = "action"         # action / perception / system


REGISTRY: Dict[str, AgentTool] = {}

def register_tool(name, description, parameters=None, timeout=10.0, risk_level="low"):
    def decorator(fn):
        REGISTRY[name] = AgentTool(
            name=name, description=description,
            parameters=parameters or _infer_schema(fn),
            implementation=fn, timeout=timeout, risk_level=risk_level
        )
        return fn
    return decorator
```

### 4.3 标准化原子动作

| 动作 | 工具名 | 参数 | 说明 |
|------|--------|------|------|
| 点击 | `click` | `element_index: int` | SoM 编号 → 坐标 → `adb shell input tap` |
| 长按 | `long_press` | `element_index: int`, `duration: float=1.0` | 坐标 → `adb shell input swipe`（同点滑动模拟长按） |
| 输入 | `type` | `element_index: int`, `text: str` | 点击聚焦 → 剪贴板粘贴 → 回车 |
| 滑动 | `swipe` | `start_x, start_y, end_x, end_y, duration: float=0.3` | `adb shell input swipe` |
| 系统按键 | `system_button` | `key: str` (back/home/enter) | `adb shell input keyevent` |
| 启动应用 | `open_app` | `app_name: str` | 应用名→包名映射 → `monkey -p <pkg> 1` |
| 状态上报 | `status` | `message: str` | 不执行操作，仅记录进度 |

**click 实现细节：**
```python
@register_tool("click", "点击标注图中指定编号的元素",
               parameters={"element_index": {"type": "integer"}},
               risk_level="low")
def click(element_index: int, som_mapping: dict, adb: AdbClient) -> ToolResult:
    if element_index not in som_mapping:
        return ToolResult(ok=False, message=f"元素编号 {element_index} 不存在")
    bounds = som_mapping[element_index]["bounds"]  # [x1, y1, x2, y2]
    x = (bounds[0] + bounds[2]) // 2
    y = (bounds[1] + bounds[3]) // 2
    result = adb.shell(f"input tap {x} {y}")
    return ToolResult(ok=result.returncode == 0,
                      message=f"点击元素 #{element_index} at ({x},{y})",
                      data={"x": x, "y": y})
```

### 4.4 统一执行入口

```python
# 模块级共享线程池（不复用每次创建销毁）
_THREAD_POOL = ThreadPoolExecutor(max_workers=4)

def execute_tool(name: str, **kwargs) -> ToolResult:
    tool = REGISTRY.get(name)
    if not tool:
        return ToolResult(ok=False, message=f"工具 {name} 未注册")

    future = _THREAD_POOL.submit(tool.implementation, **kwargs)
    try:
        result = future.result(timeout=tool.timeout)
        if isinstance(result, ToolResult):
            return result
        return ToolResult(ok=True, message=str(result), data={"output": result})
    except FutureTimeout:
        future.cancel()
        return ToolResult(ok=False, message=f"工具 {name} 执行超时（{tool.timeout}s）")
    except Exception as e:
        return ToolResult(ok=False, message=f"工具 {name} 执行失败: {e}")
```

**关键设计：**
- 线程池模块级单例，最大 4 线程（设备池规模匹配）
- 超时通过 `future.result(timeout=)` 实现，超时后 cancel 任务
- 所有异常兜底为 `ToolResult(ok=False)`，不向上抛异常
- 参数自动过滤：只传递函数签名接受的参数，避免 LLM 生成多余参数报错

### 4.5 Set-of-Mark 索引

```python
class SoMAnnotator:
    """从 Accessibility Tree 提取可交互元素，在截图上叠加编号。"""

    def annotate(self, screenshot: bytes, a11y_tree: str) -> Tuple[bytes, Dict[int, dict]]:
        elements = self._extract_clickable(a11y_tree)
        mapping = {}
        marked = screenshot
        for idx, elem in enumerate(elements, start=1):
            mapping[idx] = elem
            marked = self._draw_marker(marked, elem["bounds"], idx)
        return marked, mapping

    def _extract_clickable(self, a11y_tree: str) -> List[dict]:
        root = ET.fromstring(a11y_tree)
        elements = []
        for node in root.iter("node"):
            if node.get("clickable") == "true" or node.get("long-clickable") == "true":
                bounds = self._parse_bounds(node.get("bounds"))  # "[x1,y1][x2,y2]"
                # 排除状态栏(顶部)和导航栏(底部)
                if bounds[1] < 60 or bounds[3] > 1860:  # 1080x1920 示例
                    continue
                elements.append({
                    "bounds": bounds,
                    "text": node.get("text", ""),
                    "content_desc": node.get("content-desc", ""),
                    "clickable": node.get("clickable") == "true",
                })
        return elements

    def _draw_marker(self, img: bytes, bounds: list, idx: int) -> bytes:
        """在元素中心绘制半透明圆形 + 白色数字。"""
        from PIL import Image, ImageDraw, ImageFont
        image = Image.open(io.BytesIO(img))
        draw = ImageDraw.Draw(image, "RGBA")
        cx, cy = (bounds[0]+bounds[2])//2, (bounds[1]+bounds[3])//2
        r = 18
        draw.ellipse([cx-r, cy-r, cx+r, cy+r], fill=(0, 120, 255, 180), outline="white", width=2)
        draw.text((cx-6, cy-8), str(idx), fill="white")
        buf = io.BytesIO()
        image.save(buf, format="PNG")
        return buf.getvalue()
```

**性能优化：**
- 元素提取用 Accessibility Tree（零模型调用，<50ms）
- 标注绘制用 PIL（<100ms）
- 仅在 Executor 节点需要时标注，Manager 节点用原始截图

### 4.6 屏幕稳定化

```python
async def wait_for_stable(adb: AdbClient, timeout: float = 5.0, interval: float = 0.3) -> bool:
    """轮询等待界面稳定（UI树哈希不变），替代固定 sleep。"""
    prev_hash = None
    stable_count = 0
    deadline = time.time() + timeout
    while time.time() < deadline:
        tree = await adb.shell("uiautomator dump /dev/tty")
        curr_hash = hashlib.md5(tree.encode()).hexdigest()
        if curr_hash == prev_hash:
            stable_count += 1
            if stable_count >= 2:  # 连续2次相同判定稳定
                return True
        else:
            stable_count = 0
            prev_hash = curr_hash
        await asyncio.sleep(interval)
    return False  # 超时返回，不阻断流程
```

**谓词等待（高级）：**

async def wait_for_condition(adb, predicate: Callable[[str], bool], timeout=10.0):
    """等待直到谓词满足（如搜索结果列表出现）。"""

    while time.time() < deadline:
        tree = await adb.shell("uiautomator dump /dev/tty")
        if predicate(tree):

        await asyncio.sleep(0.3)
    return False

### 5.5 向量检索

**默认实现：sqlite-vec（零外部依赖）**
```python
import sqlite_vec

class SqliteVecStore:
    def __init__(self, db_path, dim=1024):
        self.conn = sqlite3.connect(db_path)
        self.conn.enable_load_extension(True)
        sqlite_vec.load(self.conn)
        self.conn.execute(f"""
            CREATE VIRTUAL TABLE IF NOT EXISTS pref_vectors
            USING vec0(embedding float[{dim}])
        """)

    def search(self, query_embedding: List[float], top_k: int = 3) -> List[dict]:
        rows = self.conn.execute(
            "SELECT rowid, distance FROM pref_vectors WHERE embedding MATCH ? ORDER BY distance LIMIT ?",
            (json.dumps(query_embedding), top_k)
        ).fetchall()
        return [self._get_pref(rowid) for rowid, _ in rows]
```

**可选增强：Qdrant（大规模场景）**
- 通过 `qdrant_url` 配置检测，惰性导入 `qdrant_client`
- 不可用时自动降级 sqlite-vec
- 接口一致，业务代码无感知

## 8. 异常处理矩阵

| 异常场景 | 检测点 | 处理策略 | 用户感知 |
|---------|--------|---------|---------|
| LLM 调用超时 | LiteLLM fallback | 自动切换备用模型，最后降级规则 | 无感知，可能稍慢 |
| LLM 输出解析失败 | manager/executor 节点 | 重试1次，仍失败用默认动作 | 可能任务失败 |
| 设备断连 | health_check / adb 异常 | 自动重连3次，失败标记offline，任务重新调度 | 任务延迟，SSE推送设备切换 |
| 工具执行超时 | execute_tool 线程池 | cancel 任务，返回 ToolResult(ok=False)，Manager 换策略 | 单步重试，无感知 |
| 元素未找到 | click/type 执行后 | wait_stable 后检查，失败回退 go_back 重试 | 可能多花1-2步 |
| 应用崩溃 | perception 差分检测 | 重新 open_app，从 checkpoint 恢复 | 任务延迟 |
| checkpoint 损坏 | ainvoke 时 | 降级 MemorySaver，任务从头开始 | 需重新执行 |
| 高风险动作未确认 | verifier interrupt | 超时 60s 自动取消，任务标记 cancelled | SSE 推送超时 |
| 数据库锁冲突 | SQLite WAL | busy_timeout 5s 重试，仍失败返回503 | 罕见，重试即可 |
