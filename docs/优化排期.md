## D1 完成明细（设备层）

- [adb_client.py](dro/device/adb_client.py)
  - `_screen_size()` 分辨率缓存（首得即缓存，失败不缓存兜底 1080×2400）
  - `ensure_online()` 在线态 TTL 缓存（`ONLINE_TTL=3s`）+ `invalidate_online()`
  - `screencap()` 改 `exec-out screencap -p` 直接拉流，省落地/rm 两次子进程
  - `current_focus()` 修正（不再把 `| grep` 当参数，改 Python 侧过滤）
  - 新增 `wait_for()` / `wait_for_ui_change()` 通用辅助
- 工具侧固定 sleep → 自适应等待：
  - search_product：1.2+0.6+2.0s → 等搜索框聚焦 + 等结果页加载
  - open_app：3s → 等目标包名前台就位
  - click_product：2s → 复用定位 XML 等详情页跳转完成
  - gesture：每下 1.0s → 0.5s settle

## 验收口径

- D1：端到端时长 ↓30%+、子进程调用数明显下降（需真机/模拟器复测对比）
- 每模块完成后跑 `python -m pytest tests/ -q`，须保持全绿

## D2 完成明细（模型层）

- [llm.py](dro/core/llm.py)
  - 模块级共享 `httpx.Client` 连接池（`follow_redirects` + `limits`），`chat`/`embed_texts` 复用；新增 `close_http_client()`
  - `get_llm()` 惰性 + 线程安全单例，graph 的 `_get_runtime_llm()` 改为返回单例（消除每节点新建实例）
  - `resolve_model(model)`：空/auto→None（默认 qwen），deepseek/qwen→映射具体模型名
  - `chat_with_image` 走 `_load_image_bytes()` 降采样（Pillow 最长边 1024 + JPEG q85，缺失时回退原图）
- [graph.py](dro/core/graph.py)：`GraphState.model` + 4 处 LLM 调用透传 `model`；`run_task`/`TaskRunner.invoke/ainvoke` 增加 `model` 参数
- [api.py](dro/web/api.py)：`TaskRequest`/`ChatRequest` 增加 `model`，任务/会话 store 记录并透传
- [requirements.txt](requirements.txt)：新增 `Pillow>=10.0`（可选）

> 注：意图识别结果缓存（1.1.3）暂缓——用户消息几乎不重复，命中率低且受记忆/历史影响，收益低于连接池复用；如后续评估显示重试场景多，再补 `(user_message, task_type, recent_hash, memory_hash)` 键缓存。

## D3 完成明细（工具执行层）

- [base.py](dro/tools/base.py)：`execute_tool` 改用模块级共享 `ThreadPoolExecutor(max_workers=4)`，去掉每步创建/销毁线程池（单测耗时 4s→2.2s）
- 新增 [checkout.py](dro/tools/checkout.py)：`add_to_cart` / `view_cart` / `confirm_order` / `get_product_deeplink`
  - **安全护栏**：`confirm_order` 绝不自动点「提交订单/立即支付」，仅当 `pay_auth` 命中白名单（`authorize_checkout()`）才填地址，且仍停在确认页
- 新增 [image_search.py](dro/tools/image_search.py)：`image_search`（开淘宝→识图入口→推图到设备，上传选择需设备侧完成）
- [ui.py](dro/device/ui.py)：新增 `find_any_text()` 多关键词按钮定位
- [tests/test_tools.py](tests/test_tools.py)：新增 2 条代下单安全护栏回归测试（38 passed）

## D4 完成明细（记忆层）

- [memory.py](dro/core/memory.py)
  - `SqliteStore` 进程级单例（`_default_store()`）+ `threading.Lock` 串行化读写 + WAL 模式，消除每节点重复开 2 连接的毛病
  - `LongTermMemory` / `ProfileStore` 的 Qdrant / PostgreSQL 连接改为**惰性构建**（`_get_qdrant()`/`_get_pg()`，失败降级并缓存结果）
  - `extract_and_store_preferences` 加偏好信号关键词 gate（无「预算/颜色/品牌/喜欢…」信号直接跳过 LLM）
  - `LongTermMemory.replace()`：单值偏好（预算/颜色/尺寸）显式更正，覆盖而非追加

> 注：会话摘要触发点迁移、`long_term.search()` 结果缓存、sqlite-vec 本地向量库（2.9）暂缓——摘要迁移涉及图时序改动、search 缓存对默认 SQLite 配置收益低、sqlite-vec 需新增依赖，留待后续迭代。

## D5 完成明细（编排层）

- [graph.py](dro/core/graph.py)
  - `_decide_finish` 改为**规则优先**：`_finish_by_rules()`（预算内商品 / 比价两平台 / 数量≥3）命中即结束零 LLM；不命中且 `steps_done>=3` 才降级调 LLM（步级节流）
  - `TaskRunner.invoke/resume` 加 `_DEVICE_LOCK` 设备互斥锁（单设备串行，顺带串行化 checkpoint 写入）
  - `result_node` 插入 `rank_products()`：先算分再交 LLM 生成解释
- 新增 [ranking.py](dro/core/ranking.py)：`rank_products()` 确定性评分（价格 0.5/销量 0.2/好评 0.15/运费 0.1/运费险 0.05，可覆盖），返回带 `score`/`rank`/`is_winner`
- [tests/test_regression.py](tests/test_regression.py)：新增 5 条 rank/finish 规则测试（43 passed）

> 注：checkpoint 迁移 AsyncSqliteSaver（1.6.1）暂缓——TaskRunner 用同步 invoke，切 async 需改动图编译/调用链，且设备锁已顺带消除并发写竞争；留待需要多进程/异步 checkpoint 时再迁。

## D6 完成明细（API/Web 层）
