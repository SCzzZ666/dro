## 1. 架构总览

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 固定工具集优先 | 所有手机操作通过注册的原子工具执行，禁止 LLM 直接生成 ADB 命令或代码 |
| 状态可恢复 | 每步状态持久化到 SQLite checkpoint，同一 thread_id 可断点续跑 |
| 零外部依赖可启动 | 默认 SQLite 兜底，Qdrant/PostgreSQL/Langfuse 均为可选增强 |
| 感知双通道 | 截图 + Accessibility Tree 同时采集，差分对比判断界面变化 |
| 决策与执行分离 | Manager 强模型做高层决策，Executor 快模型做单步执行，Verifier 把关高风险动作 |

### 1.2 目标架构分层

```
┌─────────────────────────────────────────────────────────┐
│                     前端层 (Frontend)                     │
│   React 18 + TypeScript + Vite + SSE (EventSource)       │
│   设计系统(CSS Variables) · 暗色模式 · 步骤时间线          │
├─────────────────────────────────────────────────────────┤
│                   API 网关层 (Gateway)                    │
│   FastAPI · Pydantic v2 · Bearer 鉴权(可选) · 审计日志    │
│   SSE 流式端点 · REST 端点 · 请求限流                      │
├─────────────────────────────────────────────────────────┤
│                 Agent 编排层 (Orchestration)              │
│   LangGraph · Manager-Executor 反馈环 · Verifier          │
│   专用文本 Agent · ReAct 规则优先结束 · checkpoint         │
├─────────────────────────────────────────────────────────┤
│                 工具与动作层 (Tools)                      │
│   标准化原子动作(6类) · Set-of-Mark 索引 · 技能包注册表    │
│   工具超时保护 · 线程池复用 · 异常兜底                      │
├─────────────────────────────────────────────────────────┤
│                 设备池层 (Device Pool)                    │
│   DevicePool · 每设备 FIFO 队列 · Worker 线程             │
│   ADB over TCP/IP · 健康检查 · 标签路由调度器              │
├─────────────────────────────────────────────────────────┤
│                 模型层 (Model Gateway)                    │
│   LiteLLM · 多供应商路由 · 强/快模型分离 · 超时降级        │
│   Qwen-VL(视觉) · DeepSeek(文本) · 可扩展任意 OpenAI 兼容  │
├─────────────────────────────────────────────────────────┤
│               基础设施层 (Infrastructure)                 │
│   SQLite WAL · Langfuse(可观测) · Prometheus 指标          │
│   Docker 部署 · 评估体系(AndroidWorld) · CI/CD             │
└─────────────────────────────────────────────────────────┘
```

## 2. 各层技术选型

### 2.1 Agent 编排层

#### 候选方案对比

| 维度 | LangGraph | CrewAI | AutoGen |
|------|-----------|--------|---------|
| 编排范式 | 状态机 + 有向图 | 角色协作 | 多 Agent 对话 |
| Checkpoint | 原生支持 SqliteSaver/PostgresSaver | 无原生支持 | 有限支持 |
| 流式输出 | 原生支持 | 支持 | 支持 |
| 学习曲线 | 中（需理解状态图） | 低（角色定义简单） | 中高 |
| 生产成熟度 | 高（LangChain 生态） | 中 | 中（微软研究院） |
| 人机交互 | 原生 interrupt | 有限 | 支持 |
| 与现有代码兼容 | 高（项目已在用） | 需重写 | 需重写 |

**决策：继续使用 LangGraph。** 理由：项目已基于 LangGraph 构建，迁移成本高；其状态机范式天然适合 GUI Agent 的"感知-决策-执行"循环；SqliteSaver checkpoint 是断点恢复的核心依赖；LangChain 生态的工具集成、追踪对接成熟。

#### 编排模式升级：Planner-Executor → Manager-Executor

| 维度 | 现有 Planner-Executor | 目标 Manager-Executor |
|------|----------------------|----------------------|
| 规划时机 | 一次性生成完整计划 | 每步执行后重新评估 |
| 反馈机制 | 无，按序盲执行 | 动态反馈环，可调整策略 |
| 失败处理 | 整任务失败 | 单步失败可重试/换策略 |
| 参考标杆 | — | Droidrun 91.4% AndroidWorld |

**状态图节点设计：**

```
[start] → [manager_node] → {task_done?}
                ↑                    │
                │              [verifier_node] (高风险动作)
                │                    │
           [executor_node] ←────────┘
                │
           [text_agent] (文本密集子任务路由)
                │
           [result_node] → [end]
```

- **manager_node**：强模型（如 Qwen-VL-Plus / DeepSeek-V3），输入当前截图 + Accessibility Tree + 上一步差分 + 任务目标 + 记忆，输出子目标 + 下一步动作类型 + 推理依据
- **executor_node**：快模型（如 Qwen-VL-Turbo），输入 SoM 标注图 + 动作类型，输出精确元素编号与参数
- **verifier_node**：仅对高风险动作（支付/删除/下单/发消息）触发，评估候选动作合理性，必要时请求人工审批
- **text_agent**：文本密集子任务专用，持有 Python shell，原子性清空替换文本，接收 Accessibility Tree（无截图）
- **result_node**：确定性打分 + LLM 生成解释文字 + 结构化输出

### 2.2 模型层

#### LiteLLM 统一网关

**选型理由：**
- 统一 OpenAI 兼容接口，屏蔽供应商差异（DashScope/OpenAI/Anthropic/本地 Ollama）
- 支持 fallback 链：主模型超时/报错自动切换备用模型
- 支持 cost tracking，与 Langfuse 集成后可量化 token 成本
- 配置文件驱动，模型变更不改代码

**模型路由策略：**

| 角色 | 推荐模型 | 选型理由 |
|------|---------|---------|
| Manager（决策） | Qwen-VL-Plus / DeepSeek-V3 | 强推理能力，理解复杂界面与任务目标 |
| Executor（执行） | Qwen-VL-Turbo | 低延迟，SoM 标注图选编号不需要强推理 |
| Verifier（验证） | DeepSeek-V3 | 文本推理，判断动作合理性 |
| 文本 Agent | DeepSeek-V3 / Qwen2.5-72B | 纯文本任务，不需要视觉 |
| 意图分类 | DeepSeek-V3（缓存） | 简单分类，温度 0.1，结果可缓存 |

**降级链：** 主模型 → 备用模型 → 确定性规则兜底（启发式意图 + 模板拼接）

### 2.3 感知层

#### 双通道感知

| 通道 | 数据 | 用途 |
|------|------|------|
| 视觉 | 当前截图（PNG，exec-out screencap 免落地） | SoM 标注、VLM 理解界面 |
| 结构 | Accessibility Tree（XML） | 元素 bounds 提取、文本内容、差分对比 |

**Set-of-Mark (SoM) 实现：**
1. 从 Accessibility Tree 提取 `clickable=true` 的节点 bounds
2. 在截图对应位置叠加编号圆点（半透明圆形 + 白色数字）
3. 编号从 1 连续分配，排除状态栏/导航栏区域
4. VLM 输出编号 → 本地映射到实际坐标执行点击

**为什么不用纯坐标猜测：** GUI Agent 领域共识，纯坐标猜测准确率仅 40-60%，SoM 可提升至 85%+（AndroidWorld 高分方案共同选择）。

**差分状态跟踪：** 维护上一步 Accessibility Tree，每步对比当前树，判断：
- 动作是否生效（目标元素是否消失/变化）
- 页面是否跳转（根节点 activity 是否变化）
- 是否出现弹窗（新增 dialog 节点）

### 2.4 设备池层

#### DevicePool 设计

```
DevicePool
├── Device[0] (taobao_logged_in, emulator-5554)
│   ├── Worker Thread
│   ├── FIFO Queue (thread-safe)
│   └── Mutex Lock (串行执行)
├── Device[1] (jd_logged_in, 192.168.1.10:5555)
│   └── ...
└── Scheduler (标签路由 + 负载均衡)
```

**关键机制：**
- 每设备独立 Worker 线程 + FIFO 队列 + 互斥锁，保证单设备串行
- ADB over TCP/IP 支持远程真机和模拟器混合接入
- 健康检查：每 30s `adb get-state`，离线自动 `adb connect` 重试 3 次，失败标记不可用
- 任务完成后自动 `adb shell pm clear <package>` 清理应用数据，防账号串扰
- 标签路由：任务指定 `{"platform": "taobao_logged_in"}`，调度器匹配设备

**为什么不用 OpenSTF：** OpenSTF 功能完整但部署重（依赖 RethinkDB/Redis/Node 微服务），当前阶段 3-5 台设备规模下自研轻量 DevicePool 更可控，后续规模扩大可评估迁移。

### 2.5 存储层

| 存储 | 用途 | 选型 | 理由 |
|------|------|------|------|
| 关系存储 | 任务状态、会话、checkpoint、审计日志 | SQLite (WAL 模式) | 零外部依赖，单文件易部署；WAL 支持并发读 |
| 向量存储 | 长期偏好语义检索 | sqlite-vec（默认）/ Qdrant（可选） | sqlite-vec 零依赖扩展；Qdrant 用于大规模场景 |
| 结构化存储 | 用户画像 | SQLite（默认）/ PostgreSQL（可选） | 小规模 SQLite 足够；多租户时升级 PG |
| 缓存 | LLM 意图分类结果、设备分辨率 | 内存 LRU + TTL | 进程内缓存，减少重复调用 |

**SQLite 并发策略：**
- 读写连接分离（WAL 模式下读不阻塞写）
- 每库独立连接，避免跨库锁冲突
- checkpoint 写入考虑 `AsyncSqliteSaver` 异步化
- 超时设置 30s，busy_timeout 5000ms

### 2.6 可观测性层

#### Langfuse 自托管

**接入点：**
- 每个任务 = 1 个 trace
- 每个节点（manager/executor/verifier/result）= 1 个 span
- 每次 LLM 调用 = 1 个 generation（记录 input/output/token/latency）
- 每次工具调用 = 1 个 span（记录动作/参数/结果/耗时/成功失败）

**指标看板：**
- 任务成功率（按场景/设备/模型分组）
- 单任务平均步数、平均时长、P95 时长
- LLM 调用次数、token 消耗、成本
- 工具调用成功率（按工具类型分组）
- 失败原因分布（超时/元素未找到/模型报错/设备断连）

**数据飞轮：** 生产 trace 可一键导出为评估数据集，失败轨迹可回放复盘，形成"运行→评估→优化"闭环。

#### Prometheus 指标

暴露 `/v2/metrics` 端点（Prometheus 文本格式）：
- `dro_tasks_total{status,scenario}` — 任务计数
- `dro_task_duration_seconds{scenario}` — 任务时长直方图
- `dro_llm_calls_total{model,node}` — LLM 调用计数
- `dro_llm_duration_seconds{model}` — LLM 延迟直方图
- `dro_tool_calls_total{tool,status}` — 工具调用计数
- `dro_devices_online` — 在线设备数

### 2.7 API 网关层

**FastAPI + Pydantic v2**，端点设计：

| 端点 | 方法 | 用途 |
|------|------|------|
| `/v2/chat` | POST | 创建对话任务（返回 thread_id） |
| `/v2/chat/{session_id}/stream` | GET (SSE) | 对话流式推送（token + 进度） |
| `/v2/tasks` | GET | 任务列表（分页） |
| `/v2/tasks/{thread_id}` | GET | 任务详情 |
| `/v2/tasks/{thread_id}/stream` | GET (SSE) | 任务执行进度流式推送 |
| `/v2/tasks/{thread_id}/resume` | POST | 断点恢复 |
| `/v2/tasks/{thread_id}/cancel` | POST | 取消任务 |
| `/v2/devices` | GET | 设备池状态 |
| `/v2/upload` | POST | 图片上传（以图搜图） |
| `/v2/metrics` | GET | Prometheus 指标 |

**SSE 事件类型：**
- `progress` — 工具执行进度（工具名、耗时、状态、截图缩略图）
- `token` — LLM 回复分片
- `done` — 任务完成（结构化结果）
- `error` — 错误信息
- `need_confirm` — 高风险动作需用户确认

**鉴权：** 可选 `DRO_API_TOKEN` 环境变量，设置后启用 Bearer 校验中间件；缺省关闭以保持零配置可用。

## 3. 关键设计决策记录 (ADR)

### ADR-001：固定原子工具集 vs LLM 生成代码

**决策：** 固定原子工具集。
**理由：** LLM 直接生成 ADB 命令或 Python 代码存在不可控风险（误操作、无限循环、权限越界）；固定工具集经过注册表校验、超时保护、异常兜底，操作可审计可重试。GUI Agent 领域（Droidrun、Mobile-Agent）均采用此模式。

### ADR-002：SoM 元素索引 vs 纯坐标

**决策：** SoM 元素索引，Accessibility Tree bounds 优先，坐标兜底。
**理由：** 纯坐标猜测准确率 40-60%，SoM 提升至 85%+；Accessibility Tree 提取 bounds 零额外模型调用，延迟可忽略；仅在 Accessibility Tree 不可用时回退轻量 UI 检测模型。

### ADR-003：Manager-Executor vs Planner-Executor

**决策：** Manager-Executor 动态反馈环。
**理由：** Droidrun 实测从 63% → 91.4% 的核心架构跃迁；GUI 环境不确定性高，一次性计划无法应对弹窗、加载延迟、页面变体；每步重新评估可动态调整策略，单步失败可重试。

### ADR-004：SQLite 默认 vs 直接上 PostgreSQL

**决策：** SQLite WAL 默认，PostgreSQL 可选增强。
**理由：** 零外部依赖可启动降低部署门槛；当前单机/小规模场景 SQLite 足够；WAL 模式支持并发读；多租户/高并发时平滑升级 PG（SQLAlchemy 抽象层隔离）。

### ADR-005：SSE vs WebSocket

**决策：** SSE (Server-Sent Events)。
**理由：** 任务进度与 LLM 输出为单向服务器推送，SSE 原生浏览器支持、自动重连、实现简单；用户停止操作用单独 POST 端点即可，无需全双工；WebSocket 增加复杂度但无额外收益。

### ADR-006：Langfuse vs LangSmith

**决策：** Langfuse 自托管。
**理由：** 开源可自托管，数据不出内网；与 LiteLLM/LangChain 集成成熟；免费版功能足够（tracing、评估、指标）；LangSmith 为闭源 SaaS，数据需上传云端。

## 4. 核心数据流

### 4.1 任务执行数据流

```
用户输入 → FastAPI /v2/chat
    → 创建 task (SQLite, status=pending)
    → 调度器路由到匹配设备的 FIFO 队列
    → Worker 取出任务
        → LangGraph .ainvoke(thread_id)
            → manager_node: [截图 + Accessibility Tree + 差分 + 目标] → LiteLLM(强模型) → 子目标+动作类型
            → executor_node: [SoM标注图 + 动作类型] → LiteLLM(快模型) → 元素编号+参数
            → 高风险? → verifier_node → 前端 need_confirm 事件 → 用户确认
            → 工具执行 (ADB 原子动作, 线程池, 超时10s)
            → 等待界面稳定 (wait_for, 轮询UI树哈希)
            → checkpoint 写入 SQLite
            → 规则判定完成? → 否 → 回到 manager_node
            → 是 → result_node: 确定性打分 + LLM解释 → 结构化结果
        → task status=completed
    → SSE 推送 done 事件
```

### 4.2 断点恢复数据流

```
用户请求 /v2/tasks/{thread_id}/resume
    → 从 SQLite 读取最新 checkpoint
    → LangGraph .ainvoke(thread_id, config={"configurable": {"thread_id": id}})
    → 从断点状态继续执行（无需从头开始）
```

## 5. 部署架构

### 5.1 单机部署（开发/小规模）

```
Docker Compose
├── dro-app (FastAPI + Agent + DevicePool)
├── dro-frontend (React 静态资源，由 FastAPI 托管)
├── sqlite-data (持久化卷)
└── langfuse (可选，独立容器)
```

### 5.2 生产部署（中规模）

```
Nginx (反向代理 + TLS + 静态资源)
├── dro-app × 2 (FastAPI，无状态，可水平扩展)
├── dro-worker × N (Agent 执行器，绑定设备池)
├── PostgreSQL (任务/会话/checkpoint)
├── Qdrant (向量检索)
├── Langfuse (可观测性)
├── Prometheus + Grafana (监控告警)
└── 设备集群 (ADB over TCP/IP，独立物理机/云手机)
```

**注意：** Agent 执行器（Worker）需与设备有低延迟 ADB 连接，建议与设备在同一局域网；API 网关可独立扩展。

## 6. 安全设计

| 层面 | 措施 |
|------|------|
| 操作安全 | 高风险动作（支付/删除/下单/发消息）必须 Verifier + 前端二次确认 |
| 数据隔离 | 不同用户任务路由到不同设备，执行后 `pm clear` 清理应用数据 |
| 输入安全 | 用户输入 prompt injection 检测；上传文件魔数校验 + 8MB 大小限制 |
| 审计 | 所有设备操作写入不可变审计日志（时间/用户/设备/动作/截图） |
| 鉴权 | 可选 Bearer Token 中间件；API 限流（默认 60 req/min/user） |
| 模型安全 | 模型配置存本地 `models.json`，不上传云端；输出不直接执行代码 |

## 7. 性能预算

| 环节 | 目标延迟 | 优化手段 |
|------|---------|---------|
| LLM 调用 (Manager) | P95 < 3s | 强模型但精简 prompt，差分状态减少输入 token |
| LLM 调用 (Executor) | P95 < 1.5s | 快模型 + SoM 标注图（小图） |
| 工具执行 (ADB) | P95 < 2s | 线程池复用、设备态缓存、exec-out 免落地截图 |
| 界面稳定等待 | 平均 < 1s | wait_for 轮询替代固定 sleep |
| SSE 推送延迟 | < 100ms | 工具每步完成即推送，无聚合延迟 |
| 单任务总时长 | 较基线降 ≥30% | 以上各项叠加 + 规则优先结束减少 LLM 调用 |
