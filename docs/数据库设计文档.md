# Dro Agent 数据库设计文档

> 版本：V1.0 | 日期：2026-09 | 状态：评审稿
> 关联文档：`技术选型与架构设计.md`、`优化开发文档.md`

---

## 1. 概述

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 零外部依赖可启动 | 默认 SQLite，Qdrant/PostgreSQL 为可选增强，通过惰性导入 + 配置检测自动降级 |
| 读写分离 | SQLite WAL 模式下读不阻塞写；每库独立连接避免跨库锁冲突 |
| 状态可恢复 | LangGraph checkpoint 独立库，每步持久化，同一 thread_id 可断点续跑 |
| 审计不可变 | 操作审计日志只追加不修改，支持合规追溯 |
| 平滑迁移 | 所有表变更通过版本化迁移脚本执行，支持回滚 |

### 1.2 数据库划分

```
data/
├── checkpoints.db    # LangGraph SqliteSaver（状态图 checkpoint，框架管理）
├── memory.db         # 四层记忆（messages/summaries/preferences/profiles）
├── tasks.db          # 任务与会话（新增，替代当前纯内存 TASK_STORE/SESSION_STORE）
├── devices.db        # 设备池与调度（新增）
├── audit.db          # 操作审计日志（新增，只追加）
└── metrics.db        # 工具与 LLM 调用指标（新增，可选，Langfuse 可替代）
```

> **分库理由：** checkpoint 写入频繁（每步一次）且由 LangGraph 框架管理，独立库避免锁竞争；audit 日志只追加，独立库便于归档与清理；tasks/devices 为业务核心，独立库便于后续迁移 PostgreSQL。

## 2. checkpoints.db（LangGraph 管理）

由 `langgraph.checkpoint.sqlite.SqliteSaver` 自动创建和管理，业务代码不直接操作。

### 2.1 表结构

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `checkpoints` | 状态图每步快照 | `thread_id`, `checkpoint_id`, `parent_id`, `checkpoint` (BLOB/JSON), `metadata` |
| `checkpoint_writes` | 节点间中间写入 | `thread_id`, `checkpoint_id`, `task_id`, `idx`, `channel`, `type`, `value` |

### 2.2 设计说明

- `thread_id` 为任务唯一标识，与 `tasks.db.tasks.thread_id` 外键关联（逻辑关联，SQLite 不强制外键）
- checkpoint 为完整状态序列化（含 messages、collected、tool_log 等），单条可能较大（数十 KB）
- 每步执行后自动写入，任务完成后保留用于回放与调试
- **清理策略：** 超过 30 天的 checkpoint 定期归档删除（`VACUUM` 回收空间）

## 3. memory.db（四层记忆）

现有库，包含 4 张表。生产化升级需新增索引与字段。

### 3.1 messages（短期记忆：对话记录）

```sql
CREATE TABLE messages (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,  -- 新增：自增主键，原表无
    session_id  TEXT    NOT NULL,
    role        TEXT    NOT NULL,                   -- user / assistant / system / tool
    content     TEXT    NOT NULL,
    token_count INTEGER DEFAULT 0,                  -- 新增：消息 token 数，用于成本统计
    ts          REAL    NOT NULL
);
CREATE INDEX idx_messages_session_ts ON messages(session_id, ts);
CREATE INDEX idx_messages_ts ON messages(ts);          -- 新增：全局时间索引，用于清理
```

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键（新增，原表无主键） |
| session_id | TEXT | 会话 ID，格式 `sess_<timestamp>` |
| role | TEXT | 消息角色：user/assistant/system/tool |
| content | TEXT | 消息内容 |
| token_count | INTEGER | 消息 token 估算（新增） |
| ts | REAL | Unix 时间戳（秒） |

### 3.2 summaries（会话摘要）

```sql
CREATE TABLE summaries (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,  -- 新增
    session_id  TEXT    NOT NULL,
    summary     TEXT    NOT NULL,
    message_count INTEGER DEFAULT 0,                -- 新增：摘要覆盖的消息数
    ts          REAL    NOT NULL
);
CREATE INDEX idx_summaries_session ON summaries(session_id, ts DESC);
```

### 3.3 preferences（长期记忆：购物偏好）

```sql
CREATE TABLE preferences (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,  -- 新增
    user_id     TEXT    NOT NULL,
    pref_type   TEXT    NOT NULL,                   -- budget_ceiling / brand_pref / category_pref 等
    value       TEXT    NOT NULL,
    source      TEXT    DEFAULT 'auto',             -- 新增：auto(自动提取) / manual(用户显式更正)
    confidence  REAL    DEFAULT 1.0,                -- 新增：置信度 0-1
    ts          REAL    NOT NULL,
    UNIQUE(user_id, pref_type, value)
);
CREATE INDEX idx_preferences_user ON preferences(user_id, pref_type);
```

**偏好类型枚举：**

| pref_type | 说明 | value 示例 |
|-----------|------|-----------|
| budget_ceiling | 价格上限 | "200" |
| brand_pref | 品牌偏好 | "Sony, Bose" |
| category_pref | 品类偏好 | "降噪耳机" |
| color_pref | 颜色偏好 | "黑色" |
| platform_pref | 平台偏好 | "京东" |

### 3.4 profiles（用户画像）

```sql
CREATE TABLE profiles (
    user_id      TEXT PRIMARY KEY,
    profile_json TEXT NOT NULL,                     -- JSON：结构化画像
    updated_at   REAL NOT NULL
);
```

`profile_json` 结构示例：
```json
{
  "user_id": "u_xxx",
  "preferred_platforms": ["京东", "淘宝"],
  "budget_range": [0, 500],
  "recent_categories": ["耳机", "键盘"],
  "task_count": 42,
  "success_rate": 0.78
}
```

## 4. tasks.db（新增：任务与会话）

替代当前 `api.py` 中的纯内存 `TASK_STORE` / `SESSION_STORE`，支撑服务重启后任务列表仍可见与 resume 恢复。

### 4.1 tasks（任务表）

```sql
CREATE TABLE tasks (
    task_id      TEXT PRIMARY KEY,                  -- 格式：<timestamp>-<uuid8>
    thread_id    TEXT NOT NULL,                     -- LangGraph thread_id，关联 checkpoints.db
    session_id   TEXT NOT NULL DEFAULT 'default',
    user_id      TEXT,                              -- 新增：多租户支持
    user_message TEXT NOT NULL,
    task_type    TEXT DEFAULT '',                   -- 前端中文标签：比价/找相似/最优方案
    intent       TEXT DEFAULT '',                   -- 内部意图：price_compare/find_similar/recommend/chat
    image_path   TEXT,                              -- 找相似上传图片路径
    budget_max   REAL,                              -- 解析出的价格上限
    model_config TEXT,                              -- JSON：本次任务使用的模型配置快照
    status       TEXT NOT NULL DEFAULT 'pending',   -- pending/running/succeeded/failed/cancelled
    error        TEXT DEFAULT '',
    step_count   INTEGER DEFAULT 0,
    llm_calls    INTEGER DEFAULT 0,                 -- 新增：LLM 调用次数
    token_usage  TEXT DEFAULT '{}',                 -- JSON：{prompt, completion, total}
    duration_ms  INTEGER DEFAULT 0,                 -- 新增：端到端耗时
    result_json  TEXT,                              -- JSON：TaskResult 序列化
    created_at   REAL NOT NULL,
    updated_at   REAL NOT NULL,
    started_at   REAL,                              -- 新增：实际开始执行时间
    finished_at  REAL                               -- 新增：完成时间
);
CREATE INDEX idx_tasks_session ON tasks(session_id, created_at DESC);
CREATE INDEX idx_tasks_status ON tasks(status);
CREATE INDEX idx_tasks_user ON tasks(user_id, created_at DESC);
CREATE INDEX idx_tasks_thread ON tasks(thread_id);
```

**status 状态机：**
```
pending → running → succeeded
                  → failed
                  → cancelled
         (resume 可从 failed/cancelled 恢复为 running)
```

### 4.2 task_steps（任务执行步骤明细）

```sql
CREATE TABLE task_steps (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id     TEXT NOT NULL,
    step_index  INTEGER NOT NULL,                  -- 第几步（从0开始）
    node_name   TEXT NOT NULL,                     -- intent_node/planner_node/agent_node/result_node/manager/executor
    tool_name   TEXT,                              -- 执行的工具名（仅 agent/executor 节点）
    tool_args   TEXT,                              -- JSON：工具参数
    tool_result TEXT,                              -- JSON：ToolResult 序列化
    screenshot  TEXT,                              -- 本步截图路径（可选，用于回放）
    a11y_tree   TEXT,                              -- 本步 Accessibility Tree 快照（可选）
    duration_ms INTEGER DEFAULT 0,
    ok          INTEGER DEFAULT 1,                 -- 0/1
    error       TEXT DEFAULT '',
    created_at  REAL NOT NULL,
    UNIQUE(task_id, step_index)
);
CREATE INDEX idx_task_steps_task ON task_steps(task_id, step_index);
```

> **存储优化：** screenshot 与 a11y_tree 字段默认不存（NULL），仅在调试模式或失败任务时保存，避免数据库膨胀。截图存文件系统，数据库只存路径。

### 4.3 sessions（会话表）

```sql
CREATE TABLE sessions (
    session_id   TEXT PRIMARY KEY,                 -- 格式：sess_<timestamp>
    user_id      TEXT,
    title        TEXT DEFAULT '',                  -- 会话标题（首条用户消息截断）
    status       TEXT DEFAULT 'active',            -- active/archived
    current_task_id TEXT,                          -- 当前活跃任务
    message_count INTEGER DEFAULT 0,
    created_at   REAL NOT NULL,
    updated_at   REAL NOT NULL,
    last_active_at REAL NOT NULL
);
CREATE INDEX idx_sessions_user ON sessions(user_id, last_active_at DESC);
```

## 5. devices.db（新增：设备池）

### 5.1 devices（设备注册表）

```sql
CREATE TABLE devices (
    device_id    TEXT PRIMARY KEY,                 -- 自定义 ID，如 "emulator-5554" 或 "phone-01"
    serial       TEXT NOT NULL,                    -- ADB serial：127.0.0.1:16416 或 192.168.1.10:5555
    name         TEXT DEFAULT '',                  -- 设备显示名
    device_type  TEXT DEFAULT 'emulator',          -- emulator / real_device / cloud_phone
    os_version   TEXT DEFAULT '',                  -- Android 版本
    resolution   TEXT DEFAULT '',                  -- 如 "1080x1920"
    status       TEXT DEFAULT 'offline',           -- online/offline/busy/maintenance
    tags         TEXT DEFAULT '[]',                -- JSON：["taobao_logged_in", "jd_logged_in"]
    current_task_id TEXT,                          -- 当前执行的任务
    tasks_done   INTEGER DEFAULT 0,
    tasks_failed INTEGER DEFAULT 0,
    last_heartbeat REAL,                           -- 最近一次健康检查时间
    created_at   REAL NOT NULL,
    updated_at   REAL NOT NULL
);
CREATE INDEX idx_devices_status ON devices(status);
CREATE INDEX idx_devices_tags ON devices(tags);
```

**status 状态机：**
```
offline → (adb connect 成功) → online → (分配任务) → busy → (任务完成) → online
                                     ↓ (健康检查失败)
                                   offline
```

### 5.2 device_tasks（设备任务队列）

```sql
CREATE TABLE device_tasks (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id    TEXT NOT NULL,
    task_id      TEXT NOT NULL,
    priority     INTEGER DEFAULT 0,                -- 优先级，越大越优先
    status       TEXT DEFAULT 'queued',            -- queued/running/done/failed
    queued_at    REAL NOT NULL,
    started_at   REAL,
    finished_at  REAL,
    FOREIGN KEY (device_id) REFERENCES devices(device_id),
    FOREIGN KEY (task_id) REFERENCES tasks(task_id)
);
CREATE INDEX idx_device_tasks_device ON device_tasks(device_id, status, priority DESC);
CREATE INDEX idx_device_tasks_status ON device_tasks(status);
```

> **队列实现：** 生产环境建议用 Redis Stream 或内存优先队列替代数据库轮询；本表作为持久化备份与审计记录。当前阶段数据库 + FIFO 内存队列混合实现。

## 9. 索引策略

### 9.1 索引设计原则

- 所有外键字段必须建索引
- 高频查询条件组合建联合索引（最左前缀原则）
- 时间范围查询建 `(条件字段, timestamp DESC)` 联合索引
- 写多读少的表（audit_logs）控制索引数量，避免写入放大
- 定期 `ANALYZE` 更新统计信息

### 9.2 慢查询预防

| 场景 | 索引 | 预期效果 |
|------|------|---------|
| 按会话查消息列表 | `(session_id, ts)` | 避免全表扫描 |
| 按用户查任务历史 | `(user_id, created_at DESC)` | 支持分页 |
| 按状态查待执行任务 | `(status)` | 调度器快速取任务 |
| 按设备查队列 | `(device_id, status, priority DESC)` | FIFO 取队首 |
| 审计日志时间范围 | `(timestamp DESC)` | 最近 N 条查询 |
| checkpoint 按 thread | `(thread_id)` 框架自带 | 断点恢复 |

## 10. 迁移策略

### 10.1 迁移框架

使用 `Alembic` 管理数据库迁移，迁移脚本存放 `migrations/versions/`。

```
migrations/
├── alembic.ini
├── env.py
└── versions/
    ├── 001_initial_memory_schema.py    # 现有 memory.db 4 表
    ├── 002_add_messages_id.py          # messages 表加自增主键
    ├── 003_add_preferences_source.py   # preferences 加 source/confidence
    ├── 004_create_tasks_db.py          # 新建 tasks.db 及 3 表
    ├── 005_create_devices_db.py        # 新建 devices.db 及 2 表
    ├── 006_create_audit_db.py          # 新建 audit.db
    └── 007_create_metrics_db.py        # 新建 metrics.db（可选）
```

### 10.2 迁移执行

```bash
# 执行所有未执行迁移
alembic upgrade head

# 回滚一个版本
alembic downgrade -1

# 查看当前版本
alembic current

# 生成新迁移（自动检测模型变化）
alembic revision --autogenerate -m "add xxx field"
```

### 10.3 多库迁移注意事项

SQLite 不支持 `ALTER TABLE` 的部分操作（如 DROP COLUMN、修改类型），需采用"重建表"模式：
1. 创建新表（目标结构）
2. 从旧表拷贝数据
3. 删除旧表
4. 重命名新表

迁移脚本必须包含 `downgrade()` 方法，支持回滚。

### 10.4 数据迁移（内存 → 数据库）

当前 `TASK_STORE` / `SESSION_STORE` 为纯内存，首次部署时无历史数据需迁移。服务启动时自动建表，内存数据不持久化。

## 11. 备份与清理

### 11.1 备份策略

| 库 | 备份方式 | 频率 | 保留 |
|----|---------|------|------|
| memory.db | `sqlite3 .backup` | 每日 | 30 天 |
| tasks.db | `sqlite3 .backup` | 每日 | 30 天 |
| checkpoints.db | `sqlite3 .backup` | 每周 | 7 天 |
| devices.db | `sqlite3 .backup` | 每周 | 30 天 |
| audit.db | 追加写入，按月归档 | 每月 | 永久（合规） |

### 11.2 数据清理

| 数据 | 保留期 | 清理方式 |
|------|--------|---------|
| checkpoint | 30 天 | 定时任务删除旧记录 + `VACUUM` |
| task_steps 截图 | 7 天 | 删除截图文件，数据库记录保留 |
| messages | 180 天 | 归档后删除，摘要永久保留 |
| metrics | 90 天 | 聚合后删除明细 |
| audit_logs | 永久 | 按月分表归档 |

### 11.3 空间管理

- SQLite 单文件建议控制在 1GB 以内，超过则考虑分库或迁移 PostgreSQL
- 定期 `VACUUM` 回收删除记录的空间（低峰期执行）
- `PRAGMA auto_vacuum = INCREMENTAL` 配合 `incremental_vacuum` 逐步回收

## 12. PostgreSQL 升级路径

当并发量超过 SQLite 承载能力（写并发 > 10 TPS 或单库 > 1GB）时，按以下顺序迁移：

1. **tasks.db → PostgreSQL**：业务核心，最先迁移。使用 `pgloader` 或自定义 ETL 脚本。
2. **memory.db → PostgreSQL**：messages 表数据量增长快，其次迁移。
3. **devices.db → PostgreSQL**：设备规模扩大后迁移。
4. **checkpoints.db → PostgresSaver**：LangGraph 原生支持，改连接串即可。
5. **audit.db / metrics.db**：保留 SQLite 或迁移至 ClickHouse（分析场景）。

**抽象层：** 所有数据库操作通过 `Repository` 模式封装，业务代码不直接写 SQL，切换存储只需替换 Repository 实现。
